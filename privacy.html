Data and access

Privacy Policy

Last updated: October 17, 2026

School Mail Bot is a personal application that prepares Russian summaries of school emails for the mailbox owner and their family.

Data the application reads

After the owner gives consent, the application uses the Gmail API with the gmail.readonly scope. This permission allows access to the entire mailbox; the application selects messages by configured sender addresses and received time. It retrieves message IDs, sender details, subjects, received timestamps, selected message bodies and attachment filenames. File attachment contents are not analyzed.

The application does not send or delete emails, modify their contents or request the Gmail password. OAuth tokens provide access without the password.

How the data is used

The selected text and metadata are used to produce detailed Russian summaries, identify requests, dates and amounts, and deliver reports to the family Telegram group chosen by the owner. The application does not use emails for advertising, data sales or the creation of model-training datasets.

Service providers and data sharing

  • Google: provides Gmail access after the mailbox owner's consent.
  • OpenAI API: receives the selected email's text, sender, subject, received timestamp and attachment filenames to prepare a summary. Requests use store=False; this does not exclude separate provider retention for security purposes under its terms.
  • Amazon Web Services: runs the scheduled processing and stores settings, tokens and report status.
  • Telegram: receives the completed report, including sender, subject and received time. Messages are visible to members of the selected group.

Data is shared only to provide the function described to the user. Use and transfer of information received through Google APIs are subject to the Google API Services User Data Policy, including its Limited Use requirements.

Storage and protection

Original email bodies are processed during execution and are not saved by the application in its status database or logs. The database may contain message IDs, completed summaries, report sections and delivery status. These records have a seven-day TTL; AWS performs physical deletion asynchronously. Status logs and sanitized error categories are retained for seven days. Failed jobs are retained in a queue for up to 14 days; that queue does not contain original emails.

OAuth tokens and API keys are stored in AWS SSM SecureString and in the owner's private local configuration until deleted or replaced. They are not published on this website or in the public repository. The database and queue use AWS encryption; external API requests use HTTPS.

Telegram reports and original Gmail messages are retained according to the respective services' rules. Their retention is not limited by the application's seven-day database TTL.

Revoking access and deleting data

The owner can revoke permission in Google's connection settings. This stops new Gmail access, but does not automatically delete previously sent Telegram messages or completed reports.

To stop the schedule or delete configuration, tokens and stored reports, contact the bot owner in the family group. Telegram messages must be deleted separately, subject to participants' permissions and the service's capabilities. Changes to data handling will be reflected on this page.

Contact

The family bot owner operates this application. Contact them through the family Telegram group or using the support email shown on Google's consent screen.
